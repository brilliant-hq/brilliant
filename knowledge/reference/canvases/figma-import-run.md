# A Figma import: the run and after

What happens from the moment you press Import on the import screen (`reference/canvases/figma-import`).

## The run

Press **Import** (or **Update**). Only now is the project created. You stay on the import (on the desktop the project gets no tab and is not opened; until the import ends it cannot be opened from Home or the switcher, and its Home tile and row show it locked: the name dimmed with a lock, "34 of 312 pages" over a bar, "Importing · about 52 min left"; a click on it brings the import forward), and the same page becomes the progress view: "Importing <file>", "n of m pages", a bar, every page with where it lands (its folder, or "Top level"), and the page landing right now. While the plugin works on a big page, the row says how far it is ("walking 12,400 nodes", "12,400 nodes, 38 images, 120 MB", "sending 40 of 120 MB"), and when nothing has arrived for half a minute the hint names the stage ("Still exporting images on Base Gallery: 38 images, 120 MB so far."). Keep the Brilliant plugin open in Figma until the import finishes. The project being imported is view-only until the import finishes, paused included (a project that was already open when its Update started stays on show to look around, but an edit, yours or an agent's, is refused with '"<project>" is still importing. You can edit it when the import finishes.' and **Show progress** brings up the import); its Home tile and row show the run: importing, "Paused · Resume", "n pages failed · Retry", then "Imported · Open" until you open it, across a restart too. A run that ended with pages failed unlocks the project as it is (Retry still lands the rest). You can keep working in other projects meanwhile: pages you are not looking at are written without entering the editor, so clicking, shortcuts, panning, switching canvases and projects all work; if a page refreshes the canvas you are looking at, that canvas dims for the seconds it takes to land. **Hide** closes the page and the run goes on, reported on its card in the notification rail (the card's **Show details**, the palette's "Resume Figma import: <file>", the "+" page's Figma row or the plugin's own Show Brilliant bring the page back in its current state); Escape or a click outside the page is the same as **Hide**: the run goes on, reported on its card. Only **Cancel import** cancels: the plugin stops at once, what landed stays in the project ("What landed before the cancel stays in <project>: n pages."), and a project this import created is never deleted ("No page had landed yet. <project> was created and is empty."). There is no Cancel in the plugin; cancel from Brilliant.

When it ends the page says **All n pages imported** with the lines ("32 pages in 8 folders", "16 empty pages skipped": an empty page mints no canvas), the end notes, **Migration report** and **Open project**. A page that did not arrive is listed in red, "Brilliant did not receive this page", with **Retry**, which asks the plugin for just that page; a late arrival still counts, so a run that ended partial can turn complete while you watch. A plan the plugin refused says why: a view-only file, no importable pages, or a Brilliant older than the plugin expects. In the browser a page the tab cannot hold is listed in red with "This page is too large to import in the browser. Import it with the desktop app." and no Retry: the browser tab has a fixed memory ceiling, so pages past about 25,000 nodes (or about 64 MB of page data) are refused before they arrive and the other pages import as usual; the desktop app imports them. A page over the limit for sending from Figma (about 64 MB of page data at once) is listed in red with its size and the limit: "Too large to send from Figma (70 MB, limit 64 MB)", with no Retry; import that page with the desktop app. The plugin never sends it, and the run goes straight on to the next page. The footer's **Retry n pages** counts only the pages a retry can land; when every page that did not land was refused this way, the footer offers **Get the desktop app** (the download page) instead. A refused page also offers **Open in the desktop app** on its row: the desktop app opens (or the download page, when none is installed), asks the plugin for that one page and imports it into its project for the file, with no second press in Figma; the footer and the pill then read "N pages landed, 1 needs the desktop app".

**The Migration report** is a canvas written into the project on every run, last in the canvas list and rewritten in place on a re-import: what arrived (pages, elements), what degraded (each page's warnings with counts, "+ N more on this page" when a page has more than its card lists), and what needs attention. The full list of issues, one line each, is also written to the app log (`brilliant.log` in `~/.config/brilliant/logs`; in the browser, the browser console), so it is still there after the notices go away. A send from the plugin, a pasted Figma selection or an SVG import whose notice reports issues carries **Show all**: it opens a card listing every issue of that import as text you can select and copy (**Copy all** copies the whole list), and **Show Import Issues** in the palette reopens that card after the notice is gone. If you do not open it, the notice still goes away on its own after a few seconds; while the card is open the notice stays, and it goes away on its own after you close the card. The first card, "Having trouble with this import?", says you can ask your agent in Brilliant: how an agent finds and reads the report, what it can fix itself and what only you can press: `reference/canvases/figma-import-help`; what each section means: `reference/canvases/figma-import-report`. A component imported as a local copy lists the property sets the import made beside it ("Button · 12 instances · 3 property sets (Show icon, Icon, Show focus indicator)"): a boolean or instance-swap property of a Figma component becomes its own small component set next to the copy on the Components canvas, so the canvas holds more masters than the file had components, and the copies line counts them ("imported as local copies, with 11 property sets beside them"). Importing the file again also removes the masters an earlier import left on the Components canvas that nothing in the project uses, and the report names them ("2 unused masters removed"); a master you made yourself is never removed.

**Fonts.** A text keeps the font family its Figma node carries, whether or not this computer has it. A text font Brilliant cannot serve here is shown in a substitute so the text stays editable (a close open font: Arial as Arimo, Times as Tinos, Calibri as Carlito, SF Pro and Segoe UI as Inter, otherwise Inter), and the end card says so: "518 texts used 3 fonts that are missing", then one row per font with how many texts use it and a picker showing the substitute ("suggested"). Pick another font in the row and every text using that font changes at once, with Undo; the pick is remembered for this project and applied on the next import ("your choice last time"). Icon fonts (Material Symbols and the like) have no substitute: their texts are drawn as outlines, said on one line. A font that is installed but lacks a weight the file uses gets a row captioned "nearest weight". **Install font files** installs .ttf or .otf files, and texts shown in a substitute switch back to the real font in place. Later: the inspector's Typography section shows a badge on a substituted text with Replace and Install font files, and the palette's "Replace missing fonts" lists the project's substituted fonts. A text whose font Figma itself reports as missing keeps that family and is counted; a text the plugin could read no family for is rendered in Inter and the page's warnings say so. Strokes on text come across like strokes on shapes, drawn on the glyph outlines; a stroke paint Brilliant cannot draw on text is counted in the warnings, never dropped silently. Which fonts Brilliant can serve: `reference/ui/inspector-sections`, "Fonts on Figma import".

## Importing the file again

Import the same file again (the plugin's **Import again** after a run, or Import to Brilliant on a file Brilliant knows) and the Project step preselects **Update**. Pages are matched by their Figma page identity, not by name: a canvas you renamed or moved into another folder in Brilliant stays where you put it and is refreshed in place, a page you leave unpicked is not touched, a page deleted in Figma keeps its canvas, and a new page lands beside its neighbours. A refreshed canvas becomes what its page holds in Figma now: anything you drew on an imported page's canvas is replaced with it, so keep your own work on canvases of your own, or leave that page unpicked. The imported design system is updated in place, components keep their one master instead of growing a copy, and the Migration report is rewritten.

**Numbering.** Canvases are named with a page-number prefix that keeps Figma's order ("1 Cover", "2 Home"; zero-padded to the count, "01" to "48", so listings that sort names as plain text keep the order). A page you unpick takes no number, exactly like an empty page, and the pages after it close the gap: "Import 3 of 48 pages" lands "01", "02", "03". When you Update with only some pages picked, a page the project already has keeps its canvas, its folder and its number, and the Pages step shows it that way before you import (the "Designs" folder of a project that holds "04 Designs" reads "04 Designs", with its pages' own numbers); a new page of a section the project already has joins that folder after its last number. Only a section that is new to the project is numbered from 1 again, beside the canvases you already have. Importing every page renumbers the import's own canvases to the file's order (a canvas you renamed or moved stays where you put it). Switch the numbering off on the Pages step if you would rather have the plain page names.

## When an import is slow or stuck

- A page can genuinely take minutes: the plugin walks every node, exports the images, then sends the bytes, and the row line says which of those it is on. Fresh progress means it is alive, even past a quiet minute.
- The plugin keeps working while Figma is in the background. One thing Figma itself may hold until its window is visible is the reference picture it renders of a page: if a row sits on that stage, bring Figma to the front for a moment; after a minute the run continues without the picture anyway.
- "Waiting for another import to finish." means another Figma import is landing in this app. Imports land one whole import at a time, so this one lands nothing until the other import has ended (every page in, cancelled, or stopped), then it starts on its own. The plugin of the waiting file shows the same line on its Importing screen. Nothing is lost while it waits, and it is not a stall. Pressing Import in a second Figma file while one is importing opens that file's own screen; the first import keeps going on its card, and its page comes back from the card's Show details, the plugin's Show button, or the pill.
- "Nothing has arrived for a while. The import may still be running.", with "Last heard from Figma: <page>, <progress>", means Brilliant has heard nothing new for a while. Check that the plugin is still open in that file and that Figma is not showing a dialog. Closing the plugin mid-run ends the stream; reopening it in the same file resumes it (the bullet below). The wait is bounded: if nothing arrives for three more minutes the run ends, the pages that did not arrive read "did not land" with Retry, and the line reads "The Figma plugin stopped sending. Reopen the plugin in Figma and run it again." (the Figma tab or the plugin died, so it is no longer connected). While the plugin is still connected the run ends the same way without that line: the pages that did not arrive rest in red with Retry. Reopen the plugin in that file and press Retry on the page, or Import again: the pages converge onto the same project. A page the plugin reports as fully sent that still has not reached Brilliant after a minute and a half is listed in red with **Retry** right away, before that wait: press Retry and the plugin sends it again. A page the plugin could not send (its panel says "failed to send") is listed in red with **Retry** as soon as the plugin moves on to the next page, and the plugin tries it once more on its own. From plugin 1.7.5 the plugin tells Brilliant the moment a send fails, so the page is listed with **Retry** at once, the last page of the import too.
- Very large pages stream in pieces. While Figma loads such a page the row reads "reading" (the hint: "Figma is still reading <page>."), then "walking 1,200 of 20,000 nodes, frame 3 of 40". Figma can stay busy for many minutes on a page with tens of thousands of layers, so in those two stages Brilliant waits up to 15 minutes of silence before it says nothing has arrived.
- You can press Import while the Libraries step is still reading the file: the run page opens at once and says "Checking libraries" under the rows while Brilliant finishes reading them (at most a minute), then the import starts with exactly the choices the Libraries step would have preselected for you (libraries you already have get connected, a library not in Brilliant becomes a new library or local copies as the step's rule says). If the libraries could not be checked within that minute, the import goes ahead with local copies and says so on the Done page and in the Migration report ("Libraries could not be checked in time; components were imported as copies. Re-import to link them."); a library Brilliant finds after that lands as copies too. If nothing arrives from Figma within a minute of the import starting, the run page says so and asks you to close and reopen the plugin, then Import again.
- If the plugin closes mid-import (or Figma quits), reopen the plugin in the same file: it reads "Import in progress: N of M pages landed" with **Resume** and **Start over**. Resume sends only the pages (and the parts of a large page) that have not landed into the same project, and the run page keeps its rows; Start over begins a fresh import. With a plugin older than 1.7 the pages that did not land show Retry, or press Import to Brilliant again, pick only those pages, and they converge onto the same project. A run that went quiet keeps its page and its card for three more minutes, so it can be resumed or cancelled; after that it ends with Retry on the pages that did not arrive.
- If the connection to the plugin drops mid-import (for example while Brilliant updates), the run page says "Reconnecting to the Figma plugin." The plugin reconnects on its own and the import picks up where it stopped: a page that was on its way is finished, sending only what Brilliant is missing. Keep the plugin open in that file. If the plugin does not come back, the run ends after the same wait as above.
- While the plugin is closed mid-import, the run page in Brilliant says "The Figma plugin was closed. Reopen it in Figma to continue." instead of waiting as if Figma were still reading. Pages Brilliant already received keep landing. When you reopen the plugin and press Resume, the page goes back to showing progress.
- If Brilliant itself quits mid-import (or crashes), open it again and press the plugin in the same file: the same "Import in progress: N of M pages landed" face appears, and Resume lands the rest in the same project. Brilliant keeps the run and the pieces of a large page it had already received, so nothing already landed is imported twice. While the run waits for the plugin, its page in Brilliant reads "Brilliant restarted during this import. Open the Brilliant plugin in Figma and press Resume to finish it."; the plugin's own panel, if it was open through the restart, ends the page it was sending with "Brilliant restarted while this page was being sent" and then offers Resume by itself.
- A page that failed has its own **Retry** on the page and on the card.
- If a run never gets past "walking" on one enormous page, cancel, uncheck that page, import the rest, then import that page alone.
- "Too large for browser: use Figma Desktop" on the plugin's Copy selection is a clipboard limit of Figma in the browser: use **Send selection**, or copy from the Figma desktop app.

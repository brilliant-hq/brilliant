# Importing from Figma

Brilliant imports a Figma file through the **Brilliant Figma plugin** (in Figma: Plugins, search "Brilliant"). The plugin is the connection to Figma: it reads the file and sends what Brilliant asks for. Everything you decide, you decide inside Brilliant, on the **import screen**. Copying a selection in Figma and pasting it into Brilliant (Cmd+V) also works, with no plugin at all: `reference/editing/figma-paste`. What the plugin itself shows, Send selection and Copy selection, and the browser limits: `reference/canvases/figma-plugin`. The run, its report and fonts, importing again, page numbering and slow or stuck imports: `reference/canvases/figma-import-run`.

## Starting an import

- **From the plugin.** Open the file in Figma, run the Brilliant plugin and press **Import to Brilliant**. With the desktop app running, Brilliant comes to the front with the import screen open. In the browser (Figma on figma.com, or no desktop app on this computer) the plugin offers **Import in the browser** instead: a new tab opens at brilliant.design/playground, signs you in if you are signed out, and shows the same screen there. The first time it asks "Connect the plugin in <file> to <account>?" with Connect and continue; later presses need no prompt while the accounts match, and a mismatch is named with a one-click switch. Pressing Import to Brilliant again while that tab is open opens nothing new ("Brilliant is open in your browser. Switch to the Brilliant tab to continue.").
- **From a Figma link.** Paste a Figma file link into the link field of the **"+" New project page** (the island's "+", or Home's New project) and press Import or Enter. The screen opens in its waiting state, "Open the Brilliant plugin in <file>", with **Open in Figma** (Brilliant opens nothing by itself). Open the plugin in that file and the screen fills in; a plugin open in another file says so, with the choice to import that file instead. The wait ends on its own after 15 minutes. On brilliant.design the link field is in the navbar's "+" menu: in the editor the screen opens right there; anywhere else the window goes to the playground and opens it there.
- **"Import from Figma"** in the palette opens that same link field.
- **A .fig file** (Figma's Save local copy) dropped on the window, on a canvas or Home, is not opened yet: Brilliant says "Brilliant can't open .fig files yet. Use the Figma plugin to import." with **Import from Figma**, which opens that same link field. Other files dropped with it import as usual.

A plugin older than 1.7 does not know the screen: it shows its own page list and imports the way it always did (`reference/canvases/figma-plugin`, "With an older plugin"). Update the plugin in Figma to get the screen.

## The import tab (new interface, desktop)

In the new interface a Figma import opens as **its own tab** on the top strip, after your project tabs and beside Settings (they keep the order you opened them in). The tab shows the Figma logo and the file's name; every way in (the plugin's Import to Brilliant, a pasted link, a dropped .fig, **Import Figma file...**) opens that tab or brings it to the front, and pressing the same file again goes back to its own tab rather than a second one. While the import runs the tab shows the time left and a thin progress line along its bottom edge; when it finishes it reads **Ready** (a green check when you are elsewhere), or **n failed** with a red mark. The tab never folds into the "more tabs" menu.

Inside the tab the setup reads like Settings: a list of steps on the left and one page per step. **Project** (the new project's name and visibility, or Update for a file Brilliant already has), **Pages** (the pages to bring in, with **Options** under them: Group into folders and Remove numbering), **Libraries** (one row per library the file uses, each with its choice: Linked, New library or Copies; while Brilliant is still checking the file a "Looking for libraries" row spins), and **Review** last. Click any step at any time; **Previous** and **Next** at the bottom move between them, and the line beside them says which step you are on, or what to fix ("Select at least one page to continue"). **Import** is on the last step: Review, or Pages when the file uses no library ("None in this file"). On a library's page the choices are listed with a radio ("Use your library", "Use the public library", "Make it a library", "Create local copies"); **Pick a different library** opens the picker as its own page, with **Back** and **Choose** and what the choice costs written beside them. Review lists every library with its choice and **Change**, then the components that can only be local copies; it works while Brilliant is still checking the rest of the file, and libraries it finds join the list.

Closing the tab before Import asks **Discard this import?** (**Keep setting up** or **Discard**): your page picks and options are not kept, and nothing was imported yet. Closing it while the import runs just hides it: the run goes on, and you bring the tab back from the run's notification (**Show details**), the plugin's Show Brilliant, or, for a .fig, the project's Home tile. The run, its results and anything that failed show inside the tab. **Open project** on the results opens the project and closes the import tab.

## The steps

The screen is a wide page over the editor, with the steps **Project** and **Pages** (and a third, Libraries, when Brilliant can rebuild team libraries), the footer **Cancel | Back | Continue** on every step and **Import** on the last. Cancel or Escape before Import withdraws everything: nothing has been created yet, not even the project.

1. **Project.** For a file Brilliant has not seen: "New project", with the name prefilled from the Figma file (the next free name: "Orbit", then "Orbit 2") and selected, so typing replaces it. For a file Brilliant already holds: **Update <project>** is preselected ("in Brilliant as <name>, updates in place", "last import <when>"), beside **Import as a new project**, which reveals the name field with the next free name. A file that looks like a copy of a known project reads "This looks like a copy of <name>. Update the project you have, or keep this one separate." and nothing is preselected until you choose. A view-only file cannot become a new project (the choice says so), so only Update runs. In the desktop app, a file you imported into one of your **cloud** projects (from the browser, or from another computer) is found too, even when nothing of it is on this computer: **Update <handle>/<project>** is offered, and its card says "In your account. It is downloaded to this computer first and kept in sync, so the libraries it already uses stay at their releases." Pressing Import downloads the project into your Brilliant projects folder as a synced folder (exactly what "Make available offline" does on the Home) and the pages land there; a download that fails starts nothing and says so. The Project step never waits for the libraries: Continue works at once, while Brilliant looks up the file's libraries in the background (several at a time) and fills in the Libraries step as the answers arrive.
2. **Pages.** The file's pages as a tree drawn like the file explorer, each with a checkbox, all picked. Uncheck what you do not need and the button follows you ("Import 12 of 48 pages"); the filter box narrows what you see, never what you picked. The list is flat by default. **Group into folders by divider pages** turns the file's divider pages (an empty page named `---` or `--- Mobile ---`, or the empty section-name page under such a line) into folders named by the divider, emoji and capitals kept, with the pages after each one inside; the divider pages themselves are not imported. Folders sit above pages at every level, in name order, exactly the way the project will read. Drag a page into another folder, double-click a name to rename it, right-click for more, add a folder with **New folder**, or switch the page numbering off. Styles, Assets and Imports are reserved for Brilliant's own folders: a derived folder that would take one of those names shows as "Styles (Figma)", and typing one into a folder name is refused in the field with "<name> is reserved by Brilliant" (page names are not reserved). A file you imported before opens with the arrangement from that import and says so ("Using the arrangement from this file's last import"); **Reset to default** returns to the first-time default, the flat list, every page picked, the file's own names and numbering kept, whatever was remembered. The control shows whenever something differs from that default.
3. **Libraries** (the import screen's third step, shown for every file). One library per screen, in the order Brilliant finds them while it reads your picked pages; the spinner beside the crumb turns into a check when it has read the whole file. Each screen offers cards: **Use your library**, **Use your team's library**, **Use @owner's library** (a private library another account owns and shares with you) or **Use the public library** (stay connected to a library Brilliant already has), **Make it a library** (Brilliant creates one in your account, through your Figma connection) or **Create local copies** (editable copies on the project's "Components" canvas). **Next** walks to the next library and on to the review, where **Change** reopens any library. **Import** is on every screen: Brilliant chooses for the libraries you haven't reached yet (connected when you already have the library, a new private library on a paid plan, local copies otherwise). While Brilliant is still checking whether it already has a library, its screen says "Checking whether Brilliant already has this library" with a spinner and offers only local copies; the answer replaces it in place with the library's real cards. Components Brilliant can't read (no library info, or a library this Figma account can't open) are always local copies, listed once on a closing screen. The step reads "No libraries in this file" when there is nothing to decide. Brilliant remembers every library's choice for this project and preselects it on the next import of the file. What each card does, Pick a different library, Verified, and a file that is itself a copy of a library: `reference/libraries/figma`. The strip above Import sums up the choices ("3 libraries connected, 1 new library, 2 libraries as local copies"), and the end of the run says what actually happened ("Orbit Icons is now a library"); a line about something that did not happen (libraries not looked up because the Figma connection expired, a library that could not be downloaded) carries a warning mark instead of a check.

A summary line above the Import button says what will land: "32 pages into 8 folders, numbering kept", "no folders", "numbering removed". Pages left out and empty pages are not counted.

**Narrow windows and large text.** However narrow the window or large the interface text, the import screen and its run page keep every sentence whole: a sentence wraps onto more lines and is never cut off with "...". That covers the card sentences, the cost line under **Pick a different library**, its sort hint, the summary line, the Project step's labels, the footer status beside the buttons, and the review and closing rows (a long count line wraps first, its reason sits on its own line under it). Only a name or a count is ever shortened with "..." when there is no room for it, such as a long library or page name. Nothing folds away into a menu: the footer buttons always stay, and the status beside them wraps into the room they leave. On the last library screen and the review, the connected line and the summary stay pinned at the foot and the list above them scrolls when the screen is short. On the run page each page row keeps the page name on its first line (shortened if it must be) and its note whole on a second line. The import's notifications follow the notification rule in `reference/ui/top-toolbar` (the detail on its own wrapping line, the stack scrolling when taller than the window).

**Where the project lives.** In the desktop app a new project is **local-only**: a folder under your Brilliant projects directory, signed in or not. Publishing it to the cloud is a separate, deliberate choice you make later (Settings, Project tab). In the browser the new project is a cloud project, and the playground tab becomes it. There the Project step also asks **Visibility**: a **Public** | **Private** switch, with one line under it that says what your pick means, worded as "+ New project" words it (Public: "Anyone can view and fork it", Private: "Members and invited people only"). Private is chosen when your plan (or, acting as a team, the team's) holds private projects; on a plan that does not, Public is chosen, Private is locked, and the line under the switch says "Private projects need a Personal plan" (or "a Team plan"). Update and Import as a new project keep the existing project's visibility and ask nothing.
**Linking libraries.** When the import connects or creates a library (a library you chose to use or to make on the Libraries step, or a matched library Figma could not name), the run shows a last step, "Linking libraries", after the pages: a spinner while the libraries are set up and the imported copies are paired into library instances, a check when that ends. The import is done only when that step ends, so what you see on the pages is final. If a linked library could not be downloaded, the step ends with a red mark and "A library could not be downloaded": the import is done, its components stay as local copies, the Done page and the Migration report name the library, and the pairing runs by itself the next time the download lands (Try again in the Assets panel, or open the project again). While the step runs it says what it is doing beside its name ("Downloading Landify", "Matching Landify", "Linking Landify, 12 of 316", "Updating pages for Landify, 3 of 30"), so a long tail on a big kit is never a silent spinner. Linking has a budget of ten minutes per library: if it is not done by then the step ends with "Linking took too long, the copies were kept", the import is done, what was linked stays linked, the rest stay local copies, and importing the file again retries.

**Components from other Figma files.** Components the file uses from a Figma team library are listed in the Migration report, one card per library, each component with how many instances use it. The card says what happened to them: "2 components (8 instances) linked to Core UI" when the import screen's Libraries step connected that library (the instances are live `lib()` references, and no "Components" canvas is left behind), or "imported as local copies" with the reason: the library is not connected to this project, or a named reason under "Library components kept as copies" (a component that differs from the library's, or one the library does not hold at the release this project uses: a newer release may hold it, so update the library from the Assets panel or import the file again; see "Libraries from a Figma file" in `reference/libraries/figma`). A component whose copy still stands in the project is never called linked, whatever library the file named for it. The report is rewritten in place when a library connects after the pages landed, so it always agrees with the canvases and with the end notice. The report follows the canvas: when a pairing ends later (a library downloaded after the run, a sweep after you reopen the project, a re-import) the report and the Done page are rewritten to what the canvas holds, so a component the canvas links is never still listed as a copy. Overrides a pairing could not keep (the "N overrides could not be kept" notice) are named in the report under their library. A library that is not connected keeps its components as local copies on the project's "Components" canvas. Styles from a team library (color, text, effect) come across too: each becomes a token of the project's design system and the layer stays bound to it, and when you make that library a library project the import writes those styles into the library's own design system as well. Layout-grid styles are not carried. A style Figma itself could not read (unpublished, deleted, or in a library your account cannot open) keeps its values as plain colors and text settings, and the import notice counts those in one line per page ("12 layers use 3 Figma styles this file does not hold"). The same holds for a layer inside a component that Figma could not resolve to its own component (a nested icon from a library your account cannot open, or a deleted master): it is imported as a plain frame, never silently, and the import issues name it ('Component "_Nav item" uses "Essential icon", which Figma could not resolve to a component'); a library pairing then reads that component as one that differs from the library's at that layer, truthfully, so re-importing after the library becomes readable to your Figma account is what links it.

# Importing from Figma: the Brilliant plugin

**The plugin is the connection to Figma.** Everything you decide about an import, you decide on the import screen inside Brilliant (`reference/canvases/figma-import`); the plugin's own panel is small: its connection state, **Import to Brilliant**, and a selection row with **Send selection** and **Copy selection**.

**How it connects.** In the Figma desktop app, the plugin finds the Brilliant desktop app running on this computer by itself: "Brilliant is not open. Open the Brilliant app and this connects on its own." turns into "Looking for the Brilliant app" and then Ready. With no app on this computer (or when it cannot be reached) the plugin offers **Import in the browser**: the import runs through your Brilliant account in a browser tab, which the first time asks you to connect the plugin to that account. A first-time face reads "Open the Brilliant app if you have it, and this connects on its own." with Import in the browser and Download the Brilliant app.

**Figma in a browser cannot reach the desktop app.** When Figma itself runs in Chrome or Safari (figma.com) the plugin only ever offers the browser lane, even while the Brilliant desktop app is running: Chrome blocks a page on figma.com from opening a connection to an app on this computer unless figma.com holds Chrome's "Apps on device" permission and passes it on to plugins, which it does not today, and Safari blocks such a connection as mixed content, with no permission to grant. So in a browser the import lands in the Brilliant web editor (Import in the browser), and importing straight into the desktop app needs the Figma desktop app, where the local connection works. The browser lane has one limit the desktop lane does not: a browser tab has a fixed memory ceiling, so a very large page (past about 25,000 nodes, or about 64 MB of page data) is refused there with "This page is too large to import in the browser. Import it with the desktop app." and the rest of the file imports as usual. From plugin 1.7.4 the plugin stops sending a refused page at once, including what it had already lined up, and goes on to the next page. (Firefox follows a different rule and may connect locally; Brilliant has not verified it.) Newer plugin versions say this on the panel instead of "Brilliant not running": "Figma in the browser can't reach the desktop app.", with the cloud button (Connect to Brilliant, or Import in the browser on the import face) and "Use Figma Desktop to connect directly.", which opens Figma's download page.

**Send selection and Copy selection.** Select something in Figma and the row reads "<name>, 1 layer selected" or "<n> layers selected". **Send selection** sends it over the connection to Brilliant, where it lands on a canvas named after the Figma page inside a folder named after the file (made on the first send and reused after, so sends from one page gather on one canvas), at its Figma position, beside what is already there; Brilliant switches to that canvas and one Cmd+Z undoes the whole send. Sending a layer that an earlier send or paste already put on that canvas updates it in place: its components are reused (never doubled), the earlier copy of the layer is replaced where it sat, and one Cmd+Z brings the earlier version back. **Copy selection** puts it on the clipboard ("Copying", then "Copied") for you to paste with Cmd+V in Brilliant, on any canvas, as many times as you like; Cmd+C inside the panel copies too. Both carry the same design: components, variables, auto layout, text, images, effects (a pasted copy brings its images in for real only while Brilliant is connected to your Figma account; `reference/editing/figma-paste`). A selection never carries the Figma page background with it; only a whole-file import sets a canvas's background from its page (and only a canvas the import made, never one you have painted yourself).


**While a file imports** the panel mirrors the run ("Importing", the pages sent) and offers no Cancel of its own: **Cancel import** is on the screen in Brilliant, and the plugin stops at once when you press it. When the run ends the panel says so and offers **Import again**, plus **Open in Brilliant** once pages have landed: it brings the desktop app forward, and after an import into Brilliant on the web it opens the project in your browser. Brilliant holds the report (`reference/canvases/figma-import-run`).

**With no Brilliant app running** the plugin opens on the import screen face straight away, with Import in the browser one press away; it never falls back to the older panel while it looks for the app. **With an older Brilliant app** (one from before the import screen) connected, the plugin shows its older panel instead and says so: "Connected to an older Brilliant. Update the app to get the new import screen.", with a "Get the latest Brilliant" link under it that opens the download page (shown for the desktop app only, never when importing in the browser); when that app closes, the import screen face returns.

**With an older plugin** (before 1.7) the panel still runs its own import: it lists the file's pages with checkboxes, can combine every page onto one canvas, and streams the file into a new project named after it, one canvas per page, with its own Cancel. Update the plugin in Figma (Plugins, Manage) to get the import screen.

**The file's design system becomes the project's design system.** The variables and styles the file carries land as the new project's `default` design system: the one every canvas resolves through with nothing to select. A project created by importing a Figma file therefore has exactly one design system, the imported one: no starter system sitting beside it, no design-system tag on the imported frames restating which one they use, and anything you create in that project speaks the same tokens by default. Re-importing the file updates that same design system in place. A project that already has a design system of its own is never overwritten: there the imported system lands beside it, the way a page or selection import always does.

**You can keep working while a file imports.** Pages you are not looking at are built and written without ever entering the editor, so the app stays yours: click, use shortcuts, pan and zoom the canvas, switch canvases and projects. The whole run reports itself on one import card in the notification rail, which names the file, the pages landed out of the pages coming, and what is happening right now ("landing Homepage", or "receiving the next page (6.0 MB)") so you can tell a slow page from a stuck one. It appears when the first page lands and stays until the run finishes, naming any page that failed with a Retry. That covers a page that never got as far as landing, too: if the import stumbles reaching the project itself, the page it was holding is named on the card with its own Retry and stays named even after the rest of the run recovers, so a run that lost one page can never read as a clean import. If nothing arrives for a few minutes the card says so and tells you the import may still be running in the background. If saving falls behind while the import runs, that has its own tile on the same rail. The one thing that does change on screen: if the import refreshes the canvas you are currently looking at, that canvas dims for the seconds the new page takes to land, the same way a slow canvas switch does. It clears by itself.

**Components import once.** A component lands on the canvas for the Figma page it lives on, and instances on every other page reference that one master across canvases, exactly as in Figma: edit the master and every page follows. Re-importing the file keeps that one master rather than growing a second copy. A component set always imports whole, every variant, however large (a 600-variant badge set, a 1,500-icon library): the plugin sends it once per import, and every other page only points at it. Pasting a set from Figma brings the whole set too.

**Components from a team library get their own canvas.** A component the file uses from a shared Figma library (one that does not live in the file itself) lands on a dedicated "Components" canvas, listed after the page canvases, instead of being scattered next to some page's content; instances on every page reference it from there. When you combine pages onto one canvas, those components land inside a "Components" frame on that canvas instead. Re-importing reuses the same canvas or frame rather than adding another. That canvas is where library components stay when you choose **Create local copies** on the import screen's Libraries step (or **Import as copies** on the library card an older plugin's run raises); choose a **Use** card (such as **Use your library** or **Use the public library**) or **Make it a library** instead (**Link library** or **Set up library** on the older card) and they become live components from a library project, and the canvas is removed once nothing uses it (`reference/libraries/figma`, "Libraries from a Figma file").

**The design system comes with it (plugin path):** a plugin paste brings the file's design system across as a real Brilliant system, not flattened literals. Variables keep their Figma names, each multi-mode collection becomes a mode axis (a light/dark collection drives the theme toggle), and shared styles become tokens; bound nodes come in referencing those tokens instead of baked values, and any losses are named in the import warnings. See `reference/design-systems` ("Importing a Design System from Figma") for the full story.

# Adding a library

Pressing **Add library** at the bottom of the Assets tab opens the Add page in the components sheet (its **×** closes it). A library you add shows up as its own row in the Assets tab's sidebar, folded like every project there: click it to open its **All** and canvas rows (`reference/libraries/assets`). A small switch on top picks **Yours** (with the count of your own libraries) or **Public**; the page remembers your last choice while the app runs, and opens on Yours when you are signed in with a library of your own, else on Public. On the playground it opens on Public. Without a public catalog connection there is no Public tab and the page is just your list. On the signed-out playground board there is no Yours tab, and pressing Add there first saves the board as a project and asks you to sign in ("Adding a library saves this board as a project.").

The search field at the top of the window stays context-aware: on the component grid it searches components ("Search components…"); on the Add page it reads "Search libraries…" and searches whichever tab is showing, Yours by name or handle, Public through the catalog. Typing never takes you off the page, and a query never carries from the Add page to the grid or back, except "Search public libraries for", which takes your component search with it.

- **Yours**: projects you can access that are marked as libraries, each with its cover, name, handle, star count, and latest release; the line under the name starts with **Private** or **Public** when the library's visibility is known ("Private · @acme/kit · 1.4.0"). Press Add to depend on it at the latest release. The list flows down the page, however long it is, and ends with the folder row (below).
- **Public**: a **Filter by topic** button sits after the search field; it opens a menu of topics (All, UI kits, Icons, Design systems, Illustrations, Templates, Wireframes) with a check on the current one, and while a topic other than All is picked the button stays highlighted. The search narrows within the picked topic. Cards show the cover as of the latest release, the name and handle, a one-line description, then one facts line: a star with the count, how many components it has, and when it was last updated (the last two appear once the library's latest release carries them), plus the latest version. A **Verified** seal beside a card's title marks a library on Brilliant's verified list (it stands for Public, so no second word is added), and a Featured tag marks the few libraries Brilliant picks; cards on the Public tab do not repeat the word Public, and elsewhere a library reads Public or Private beside its name. Featured libraries come first, then Verified libraries, then the rest, each group most-starred first. The card grid sits right under the search, fills the page and scrolls as one; further results load automatically as you near the bottom. Searching or picking a topic always starts the page back at its top with the new matches.
- **Starring**: the star beside a library's count is a button. Press it to star the library with your account; the star fills, the count goes up at once, and it settles on the server's number. Press it again to remove your star. Stars are yours: switching accounts shows that account's stars, and switching back shows yours again. Signed out, pressing the star asks you to sign in first. If the star cannot be saved (offline), it returns to how it was and a notice says so. The same star is on the library's page. When a row is too narrow for the count, the star shows alone and its tooltip says the count.
- **A handle in the search**: paste a library's handle (`@team/library`, the @ is optional, capitals are fine) or the link to it on brilliant.design into the search field on either tab and it resolves as the first row: its cover, name, handle, latest version, and Add. If the server could not be reached, answered with an error, or did not answer within 20 seconds, the row reads "Could not reach the server."; if it is rate limiting this connection, the row reads "The server asked Brilliant to slow down. Try again in a moment." within seconds; press Enter to look again. A handle that cannot be found reads "Could not find @team/library. Check the spelling, or ask its owner to make it public."; a project that is not a library, or a library with no releases yet, says so in plain words.
- **Already added**: a library this project already uses keeps its version chip (on a Public card the Update button names the version instead) and reads "Added, 1.2.0" in both tabs; when a newer release exists the row offers "Update to 1.4.0", which opens that library's update screen.
- **The same library at a new address**: when a library moved (its owner transferred it to a team) and this project already uses it under the old address, adding the new address adds nothing. A notice says "This project already uses Acme Design System" ("It is here as @owner/kit. @team/kit is the same library."). The old address keeps working; to change its version, update it there.
- **Use a folder on this computer…**: the quiet last row of the Yours tab (desktop, folder-backed projects only). It opens the folder picker and adds the chosen folder as a live library named after the folder; a refusal appears right under the row. A folder whose name this project already uses is never swapped in silently: the row says "This project already uses a folder named <name>." (or "This project already uses that folder." when it is the same one).

## A library's page

Pressing a row or a card anywhere but its button opens that library's page. A breadcrumb on top ("Your libraries / Acme Design System" or "Public libraries / …") leads back to the tab you came from, with its scroll position and search kept. The page shows the cover, name and handle, one quiet line of facts (owner, stars, license, latest version and its date), the description (when you came from a Public card), and the primary Add (or "Added, 1.2.0" with "Update to 1.4.0" when a newer release exists). When the library itself uses other libraries, a line says what comes along: "Also brings Acme Icons 0.9.0". Below, "What's new in 1.4.0" shows that release's notes and date (absent when the release has none), then "<n> components, by canvas": a preview of every component grouped by canvas, pictures, names and variant counts; nothing can be placed from here. Looking never adds anything: nothing is written until you press Add. A library you already use previews from its downloaded copy; any other previews straight from the release. The page always says where it stands in one line: "Loading components…" (once the release's files are listed it says how far it got, "Loading components, 2 of 4 canvases…"), "This library has no releases yet.", "This library has no components yet.", "This is a project, not a library. Its owner can share it as a library.", "Could not find this library.", "Could not reach the server.", "Timed out reading its canvases." (or the release list, the release's files, its components: the step that stopped), "The components could not be loaded." or "Some components could not be loaded." (the last four with **Try again**; a server error or a release list that hears nothing for 20 seconds ends on "Could not reach the server.", never on "Could not find"; a preview that makes no progress for 20 seconds says which step timed out, since the server was answering a moment before); a server that is rate limiting this connection reads "The server asked Brilliant to slow down. Try again in a moment."; a very large library reads "This library is large. Only its first canvases are shown." While an Add is running its button reads "Adding…" and cannot be pressed twice. "Update to" is never offered for a library that cannot be fetched right now. Opened from the "Open library page" link on a library's warning banner, the page keeps that library's rail row highlighted and its breadcrumb ("Components") returns to the library's grid.

In the new interface the library page shows a **Releases** section instead of "What's new": the releases newest first, each with its date and notes, the newest marked **Latest** and the one this project uses marked **In use**. When your project is behind, the newest offers **Compare with <your version>**, which opens the update review. Older releases wait behind **Show older releases**.

Adding works **signed out** for public libraries in a project saved in a folder on this computer: browsing, resolving a handle, and fetching all work without an account (a private handle answers that it could not be found). "Yours" naturally needs a signed-in account.

Agents add libraries by writing the manifest directly, or through the library commands (`add_library`, `update_library`, `remove_library`, `add_local_library`; see `blueprint/commands`). Every library message a person sees is in plain words and names the library by its display name ("Added Acme Design System 1.2.0", "Could not find @acme/secret-kit", "You are offline"); the same command answers an agent with the precise sentence (the handle, the version, the file). A refused act shows one notice: a new refusal of the same act replaces the last one instead of piling up, it stays until you close it, and it goes away by itself when that act succeeds.

Adding, updating and removing a library (and the Undo of a removal) work the same in a project saved in a folder, a cloud project open in the desktop app, and the web editor; only a folder library needs a project folder. If the library list cannot be saved the outcome says why in plain words ("Could not save" with "You seem to be offline.", "This project was changed somewhere else" with "Try again.", or "You can view this project but not change it"), and nothing is changed. A libraries file written in a way Brilliant cannot edit safely is never rewritten: the outcome is "Could not change this project's libraries".

## The manifest: libraries.yaml

Dependencies live in **`libraries.yaml` at the project root**, one entry per library. It is plain YAML, safe to hand-edit or agent-edit, and it travels with the project when published, so anyone who opens the project gets the same libraries.

```yaml
"@acme/design-kit": "1.2.0"   # a published library, pinned to a release
my-kit:                        # a local folder library (no versions; see below)
  path: ../shared/kit
```

Editing the file is live: saving a manifest change fetches what is missing and re-syncs affected instances. For a project in the cloud, a save of the manifest built on a version the server no longer holds is refused ("This project was changed somewhere else. Try again."); nothing is merged by lines, you re-read and save again (the app's own Add, Update and Remove retry that on a fresh read up to three times before saying so; a hand edit sees it at once). An instance whose library is not declared here (or whose source canvas no longer exists) opens as a placeholder frame that keeps the reference, its size and every row it stored; select it and the inspector says what is missing (`reference/libraries/unavailable`). Declaring the library (Add library in the Assets view, or an entry here) fills it in as soon as the library arrives, no reopen needed. The version is an exact release; there are no version ranges.

## Local folder libraries

A plain folder on your machine can be a library, published or not, via a `path:` manifest entry (see above). The manifest key can be the folder's real name, spaces and parentheses included: quote it in the YAML (`"Material 3 Design Kit (Community)":`) and use the same name inside `local()` in `lib()` refs (`lib(local(Material 3 Design Kit (Community)))`); keys cannot contain `/` or `\`, start with `@` or `.`, start or end with a space, or run past 100 characters. Local libraries are **live**: there are no versions; the folder's current state is what you get, and saving a change in that folder re-syncs your instances immediately. This is the solo workflow and the author loop (iterate on a kit inside a real consumer project before releasing it). They work in projects that live on disk; the read-only rule still applies from the consumer side. Local rows in the Assets view show a "Live" marker and no version or update controls (there is nothing to update to). The Add page's Yours tab ends with "Use a folder on this computer…", which picks the folder and adds it with the folder's name as the key.

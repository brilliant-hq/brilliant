# The Assets view

**Assets is a tab of the left panel.** The narrow rail at the window's far left has an **Assets** button (the box icon); it, **Cmd+Shift+A**, and the **Toggle Assets** command open the left panel on Assets with its search focused, and the same press on the open tab hides the panel. (While the AI chat is open, Cmd+Shift+A toggles the Chat Explorer instead; use the rail, the palette, or the menu bar's **View > Focus > Assets** then.) Every other way in (the inspector's library line and its **Update to** item, the color picker's **Add library…**, and Project settings > Libraries) opens this tab too; there is no separate Assets window. From a screen with no rail (Home, or the Settings tab), Cmd+Shift+A and those ways in switch to the project tab you were last in and open its Assets tab; with no project open, the most recent project opens first. The web editor works the same way: it has the same rail (Files, Assets, Checkpoints, Project and your account at the bottom), so the bottom toolbar there has no Assets button either, and the Free chip shows as in the desktop app.

- The panel is a sidebar, one scroll: a search field ("Search components…") beside a grid / list switch, then **All components** with the count of every component you can use, then **This project** with its count, then one row per library with its version. **Add library** stays pinned at the bottom of the panel, even while you search.
- **Assets opens on All components with the sheet open**, every time you open the tab (also after you closed the sheet).
- **Projects fold.** This project and every library start collapsed; click a project's row to open or close it (a click only folds, it never changes what the sheet shows). Each project remembers whether you left it open, per project, also after a reload in the web editor or a relaunch of the app (a cloud project included). An open project lists **All** (that project's count) and then one row per canvas that holds components (its name and count, in path order), indented under a guide line like the Files tree; a project with one canvas still lists **All** and the canvas, and a project with no components says "No components in this project yet".
- **Pick a row** to open it in the **components sheet**: a second panel attached to the left panel's right edge, over the canvas. The canvas never moves or resizes for it. **All components** shows every canvas of every source in one scroll, each under its source's name, and the sheet's header names the canvas in view with its count and source. A project's **All** shows all of that project's canvases: for This project the header reads "All" with the count and "This project"; for a library it shows the library's name and version, **Update to 1.4.0** when an update waits, and a ↗ button for the library's page. **A canvas row shows that canvas only**, its row staying highlighted. Folding a project whose canvas is shown keeps the sheet as it is. A library that can't be reached shows why at the top of the sheet, with **Try again** and **Remove**.
- The sheet closes with **Esc**, its **×** button, or a click on the canvas; clicking to place an armed card does not close it. Drag its right edge to resize it (240 to 600 pixels, 352 at first); it keeps your width for the rest of the session, and widening the left panel moves the sheet along.
- **Type in the search** and the sheet opens on the results: its header reads "Results" with the number of matches and what you typed, the results are grouped by source and then canvas, and the sidebar opens every project with matches on its canvases with matches (their counts become match counts, with no All row), hides the projects without matches, and reads **All results**. Searching for a canvas's or a library's name shows all of it. Clearing the search puts every project back the way you left it and keeps the sheet open on All components.
- A library's sidebar row reads its name and version. At rest its end shows the library's state: a dot and the newer version when an update exists, a **Live** chip for a folder library, a warning glyph when it can't be reached. Hover the row and the state gives way to a **…** button (right-clicking the row opens the same menu): **Update to 1.4.0** (or **Update** when it is current; never on a folder library or one that can't be reached), **Open library page**, **Go to library project**, and **Remove**. Project settings > Libraries lists the same rows with the same menu, plus **Update all** when more than one library has an update.
- Cards show three per row in the sheet (104 pixels each; a wider sheet fits more), or one 26-pixel row each in list view. **Click a card to arm it**: the card stays highlighted and the component rides the cursor; the next click on the canvas places it, and **Esc** disarms. The sheet stays open while you place, and while you drag: dragging a card onto the canvas beside the sheet places it at the drop point, and you can drag the next one right away.
- Rest the pointer on a card for a moment to see a larger preview beside the sheet, with where it comes from ("This project · Buttons · 3 variants"). It hides while you drag.
- **Add library** opens the Add page in the sheet (its header reads "Add library", "Yours and public libraries"), with a **Yours** / **Public** switch and its own search; **×** closes it. A library's page, and an update's review, open in the main area beside the panel (where the canvas was); **Esc** returns to the panel.
- A library's page lists its components beside a **canvas sidebar**: **All components** with the total, then **Canvases**, each canvas with its number of components. Click a canvas to scroll to it (**All components** scrolls back to the top). The sidebar scrolls with the page until it reaches the top, then stays there, and the canvas you are looking at is highlighted as you scroll.
- A **folder library** has a page too (**Open library page** on its row, its sheet header's arrow, or Project settings > Libraries): the same page and sidebar, its folder path where a handle would be, the **Live** chip with "A folder on this computer. Always current.", and "Added". It has no versions, releases, release notes, stars or license, and nothing is read from the server. A folder library whose folder can't be found offers no page.
- **Placing** is one undo step and makes a normal component instance: reconfigure its variant, override its children, and so on in the inspector. A component dropped over a component that is already placed lands beside it in the same frame (or on the canvas), never inside it: a placed component's layers belong to its component. The exception is a slot, which takes what you drop on it.
- **In the web editor** a library is read in the background right after the project opens, and the browser keeps a copy of it, so Assets opens at once from then on, also after a reload. The first time a library's components are shown before that read has finished, the list says "Loading components…" and then fills in. If they cannot be read, or a read takes longer than 20 seconds, the row shows the warning glyph and **Try again** reads them again; it never stays on "Loading components…". A library component that has a picture in it shows the picture once it is placed; the picture is fetched the first time it is needed, so it can appear a moment after the component does.
- **"This project" lists every canvas's components**, not only the open ones. In a project with no folder (the web editor, or a cloud project open in the desktop app) the canvases that are not open are read in the background ("Loading components…"), and a component from a canvas that is not open can be placed without opening it. If a canvas cannot be read, Assets says "The components could not be loaded." (or "Some components could not be loaded.") with **Try again**, which reads the project again; it never says "No components in this project yet" for a project it could not read.
- A cloud project you can only view (you are signed out of it, or it is someone else's) lists its libraries and their components but offers no **Add library**, no **Search public libraries for**, no Update or Remove, and no Add on a library's page; **Go to library project** stays. A project saved in a folder is never view-only.
- **Removing a library** never edits your canvases: any instances of its components stay and simply report the library as missing (see `reference/libraries/unavailable`). While a Remove runs, the row reads "Removing…" in place of its version and offers only **Go to library project** until it ends, so it cannot be removed twice. The outcome says what it cost ("Removed Acme Design System", then "2 components on canvas now show as missing", "Nothing on canvas used it", or "Its components on canvas now show as missing" when the count cannot be exact because not every canvas is open) and carries **Undo**, which puts the library back at the same version at once (its downloaded copy is kept). A library that was replaced at its address asks first and has no Undo (`reference/libraries/unavailable`). **Go to library project** opens the library as its own tab (in the web editor, in a new browser tab, so the project you are in stays open).
- A library's components are the ones the library itself owns. Copies it holds of another Figma library's components (an icon library the kit used) are not listed, though a component placed from one keeps working; see "Foreign masters" in `reference/libraries/figma-projects`.
- **Names, not handles.** A library row reads the library's display name ("Acme Design System"); hover the row to see its handle (`@acme/design-system`). Search results are grouped under the same name. A library that has no display name shows its project name (the part after the slash), or its full handle when two libraries would otherwise read the same. The handle is still what you type in `libraries.yaml` and in `lib()`.
- **No match.** A component search with no match offers **Search public libraries for** your query, which opens the public library search with it.

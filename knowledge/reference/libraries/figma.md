# Libraries from a Figma file

Importing a whole Figma file with the Brilliant Figma plugin (`reference/canvases/figma-import`) recognizes components the file uses from a **Figma team library** and can rebuild that relationship in Brilliant: the team library becomes a library project of its own (a local folder library in the desktop app, a cloud library project in the browser), and the imported file uses its components as live library components instead of private copies. You choose library by library on the import screen, or press Import and let Brilliant choose the rest by one simple rule. What the resulting library project looks like, importing the library file itself, Make this a library, foreign masters and the older plugin's cards: `reference/libraries/figma-projects`.

## The Libraries step

The import screen's third step goes through the team libraries the file uses **one library per screen**, in the order Brilliant finds them. It opens straight from Pages: while Brilliant is still reading your picked pages, the first screen reads "Looking for libraries", and each library joins the step as soon as it is found. The bar under the header gains a segment for each one, the crumb counts where you are ("Libraries 2 of 3"), and the spinner beside the crumb turns into a check in place when Brilliant has read the whole file. Every screen of the step is the same size, so nothing jumps while libraries arrive. The connected line at the foot says which Figma account Brilliant uses ("Connected to Figma as <account>.").

Each library's screen names it as the Figma file knows it, with its component count ("214 components"; "30+ components found so far" while Brilliant is still reading), one sentence about what Brilliant already has, and side-by-side cards, one of them selected:

- **Use your library** or **Use your team's library** (**Use @owner's library** for another account's private library you can open, **Use the shared library** when it has no owner to name): the components stay connected to the library you or your team already have in Brilliant, so changes made there show up here. Its **Private** chip reads the library project as it is now: a private library shows **Private**, and a library you made public shows no chip here (only a **Verified** one shows a chip, Verified), whatever it was when it was set up. Selected when Brilliant has a library with these exact components. When your own library has these components but some were edited after the file copied them, **Use your library** says how many differ: those become local copies and the rest stay connected. A library whose components are only similar (the same family) starts on local copies. In the desktop app, when the same library exists both as a folder on this computer and as a cloud library in your account (the same Figma file behind both), **Use your library** is the cloud one, with its releases and, for a project that already pins it, the release that project uses; the folder is offered as the alternative under **Pick a different library**, never chosen silently. There the two read alike except for one fact: the cloud row shows its address and release, the folder row shows **Live** (it has no releases; it is the library as it is on this computer).
- **Use the public library**: the components stay connected to a public library Brilliant has (its **Verified** chip when Brilliant vouches for it, its version); you get its updates, but can't edit its components. Selected when it has these exact components, and also when it is **Verified** and its components are from the same family; a public library from the same family that is not Verified starts on local copies. When one of your own libraries and a public one both have the components, yours comes first and is selected.
- **Make it a library**: for a library Brilliant doesn't have yet. Brilliant creates the library in your account (the card names it, "Creates @you/orbit-icons") and connects this project to it, so your other projects can use it too. It needs your Figma connection: if that connection expired, the card reads **Reconnect Figma to make this a library** with a **Reconnect** link instead, and the library's components import as local copies until you reconnect (on the web, Figma opens in a new tab and the import stays where it is). On the Free plan, new libraries are public, and the card says so.
- **Create local copies** ("Only in this project"): editable copies go on this project's "Components" canvas. They won't get updates, and nothing new is created. Always offered.

If Brilliant's catalogue cannot take what the file sends about a library (a component set far larger than the catalogue's bounds), that library is not matched: its row reads as not in Brilliant, the import continues with local copies, and the app asks the catalogue about that file no further. The desktop log (`brilliant.log`) says "match refused" with the reason. The closing screen and the review then carry one line saying so, once per import, on the desktop and on the web: "Library matching skipped for this file: a component set has more variants than Brilliant can index."

**Pick a different library** shows when more than one library could be used. The list opens in place of the screen, on the libraries that match this file's components (plus your own library of the same name); **Show all libraries**, or a search by name or @handle, reaches the rest of the catalogue. The filters All, Verified, Public and Private narrow what is shown, each library with its coordinate, its Verified, Private or Public chip, version, stars and how close it is ("Exact match", "Same family", "Edited copy, 38 of 42 differ"), the current pick marked. Before **Choose**, the footer says what the choice costs ("Choosing @dana/m3-dark: 38 of its 42 components differ, so they become local copies."). Choose returns to the library's screen with the library you picked in the middle card, selected. When the library catalogue can't be reached, only the libraries this device already knows are offered, and nothing blocks.

**Next** walks to the next library ("Next: Orbit Core"). If you reach the last library found while Brilliant is still reading the file, Next goes to the review, which keeps filling ("Still checking the rest of the file. Libraries it finds join this list.").

**Import is on every screen.** On a library screen it is the secondary button, and its tooltip says what happens to the rest: "Brilliant chooses for the libraries you haven't reached yet, and for any it still finds." The rule: a library you already have is connected; on a paid plan a library Brilliant doesn't have becomes a new private library; everything else becomes local copies. On the Free plan, libraries you already have are connected and the rest become local copies (Brilliant never makes a public library you haven't seen). The same rule decides for a library Brilliant finds after you press Import.

**Components Brilliant can't read are always local copies.** Components with no library info ("Figma doesn't say where they come from") and components from a library this Figma account can't open never get a screen of their own: one closing screen lists them ("43 components will be local copies"). The one exception: when Brilliant has a library that matches the components of a library your account can't open (a file built on a Community kit Brilliant also has), that library gets a screen saying your Figma account can't open it but Brilliant has a matching one, with **Use the public library** beside **Create local copies**: Use the public library is selected when the matching library is Verified, local copies otherwise. Using it connects this project to that library, and once the pages land Brilliant swaps the imported components for the library's matching components, matched by name and structure since Figma won't say which library they are from: identical ones become the library's components (every instance keeps its place and its changes), a component the library has no match for stays a local copy, and the Migration report says how many linked and how many stayed copies ("3 components (7 instances) linked to Material 3 Design Kit by structure, 1 kept as a copy"), naming the ones that stayed under "Library components kept as copies" (a copy kept because a nested component was swapped for another gets a row naming both, `reference/canvases/figma-import-report`). Components with no library info get the same screen when Brilliant has a library they match ("Figma does not say where these components come from, but they match Brilliant's Material 3 Design Kit, a library from the same family."), selected the same way (Use the public library for a Verified library, local copies otherwise), and **Use the public library** links them the same way. When Brilliant isn't connected to Figma, that screen and the first one offer **Connect Figma**, so Brilliant can tell which libraries the components come from.

**The review** lists every library with what happens to it ("Orbit Core: connected to your team's library, @orbit-team/orbit-core", "Orbit Icons: becomes a new library, @you/orbit-icons", "31 components from a library this account can't open: local copies", with the account that can't open it on the line under it), each with **Change**, which reopens that library's screen and comes back to the review. On the last screen Import is the primary button with **Review** beside it. The strip above the buttons sums up the choices: "3 libraries connected, 1 new library, 2 libraries as local copies". Nothing has happened yet at that point; the end of the run says what actually happened. If Brilliant couldn't get through every component of a very large file, the review says a library may be missing, and the rule decides for it. The step always exists; with nothing to decide it reads "No libraries in this file".

**Brilliant remembers.** At Import, every library's choice (connected, a new library, local copies) is recorded for this project, per library. On the next import of the file into the same project each library opens on its record: local copies stay local copies, a library you made reads **Use your library** once it is in Brilliant, and a connected library stays connected; a library that was not on the previous import takes the usual rule. Choose another card and the new choice is recorded instead.

## When the file itself is a copy of a library

A Community kit you duplicated and imported is recognized on the **Project** step: a band reads "This looks like a copy of Material 3 Design Kit." with the library's coordinate, grade and version. **Use the public library** links the project to it and imports nothing from your copy (the end line reads "Linked to Material 3 Design Kit. Your Figma copy was not imported."); **Import my copy** imports the file as it is, and the end of the run notes that the file matches the library so you can link it later. A private match adds its own card, first and preselected: **Use your library** for your own library, **Use your team's library** for your team's, and **Use @owner's library** for one another account owns and shares with you (the band names it the same way, "@owner's library, 1.0.0."); in the desktop app this holds even when Brilliant's library catalogue can't be reached. An edited copy ("12 of 1,214 components differ") is a warning band that defaults to Import my copy.

## What the end of the run says

- **On a connected library, content decides.** Whatever the match said, each imported component is compared with the library's before it becomes a live library component: identical ones link, a component that differs stays a copy on the Components canvas, and the end line counts them ("Linked Material 3; 3 of 42 components differ from the library and stay as copies"). Two differing snapshots are never merged.
- The Done page lists what happened, one line per library connected ("Orbit Core connected") and made a library ("Orbit Icons is now a library"), then one count of the libraries that are local copies ("2 libraries as local copies"): the ones you chose as local copies, the components Brilliant can't read, and any connection or new library that did not happen (Figma refused to say what a component is, a library that could not be created). A library you connected on its screen is never in that count, whatever your Figma account can see of it: its own line says what linked. A library that could not be created never reads "is now a library".
- **No access.** Components from a library your Figma account can't open are imported as local copies, and a note on the Done page says how many and which account Brilliant is connected as. When you connected the project to a matching library Brilliant has (**Use the public library** on that library's screen), the copies that match the library by name and structure are swapped for its components as the import ends, the Done page reads "Material 3 Design Kit connected" (or "Linked Material 3 Design Kit; 1 of 4 components differ from the library and stay as copies"), and the no-access note counts only the components the pairing never reached; a component it compared is listed in the Migration report with its reason instead, so the note disappears when every component was compared. Using it on a project you imported earlier swaps that project's copies right away, with no new import. To bring them in as a library, connect a Figma account that can open it (in the palette: **Disconnect Figma**, then **Connect Figma**) and import the file again; the pages update in place. **Connect Figma** while connected says which account Brilliant uses ("Connected to Figma as <account>"), on the desktop and on the web. With an older plugin the same note is a card at the end of the import, with **Keep copies** to close it.
- **A library you chose to set up could not be set up yet.** When the setup cannot start (the project was not ready for libraries when its components landed, Brilliant needs you to connect Figma first, or libraries cannot be set up from this editor), the components are imported as local copies and Brilliant says so: a notification titled "Library from <file> not set up" with the reason, the same reason on the Done page and in the Migration report under "Components from other Figma files". If the project was simply not ready, Brilliant sets the library up by itself as soon as it is, with no new import; otherwise follow the reason (connect Figma, then import the file again). The same notification and report line cover a setup that started and could not finish: Brilliant could not check which libraries your account already has, the library exists but the components could not be added to it or found in it, the library could not be created from the imported components, or Figma named the library by a different file than the import screen did. Each says what to do next (try the import again, or see the report).
- **A library you already have is linked, never copied.** When the file uses a library that already exists in your account (set up from this or another browser), its screen on the Libraries step opens on **Use your library**, and if the setup only finds that out while it runs, it links the existing library instead of creating a second one or adding to it: the instances become live library components, the note reads "Linked @you/library", and the report says how many components were linked to it.
- **Your Figma connection needs attention.** Expired: when Figma no longer accepts Brilliant's connection (and Brilliant could not renew it on its own), the Libraries step says "Your Figma connection expired. Reconnect to name the libraries in this file." with one link, **Reconnect**. Until you reconnect, nothing is looked up and those components read as unnamed; after you reconnect, the libraries are read again in place. If you import anyway, the import report says the libraries were not looked up because the connection had expired. **Connect Figma** in the palette says the same and reconnects. Older than library support: the Libraries step's connected line says so ("This connection was made before Brilliant could read libraries, so they import as copies.") with one link, **Allow library access**, which opens the Figma connect page once more and then reads the libraries in place. Elsewhere, the first time Brilliant needs to read library information it opens the Figma connect page once more. Skip it and the components are imported as copies, and the end note says so.
- Pages you already imported are converted in place when a library is connected or made, so you do not need to re-import them. The note at the end is short: a title such as "Core UI library updated" and one or two sentences, for example "4 components in this file differ from the library and stay as copies. The report lists them." Its **Go to library** button opens the library project and **See report** opens the project's Migration report, where a "Library components kept as copies" section names every component that stayed a copy, grouped by reason (every reason heading, what it means and what helps: `reference/canvases/figma-import-report`), and lists any notes from setting up the library. A page that could not be updated is named there too, and importing that page again finishes the job.
- **Imports only ever add to a library project.** Importing a file that uses the library never changes a component the library project already holds, and anything you edited there yourself is left alone and named in the Migration report. A component that changed in Figma between imports stays in the importing project as its own component and the Migration report names it; importing the library file itself is the moment everything converges.

Copy and paste from Figma, Send selection and Copy selection never create library projects; they bring components along as part of what you pasted.

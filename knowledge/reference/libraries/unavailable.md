# Read-only and unavailable libraries

## Where library files live, and why they are read-only

For a project folder on disk, a library's files are downloaded into **`.brilliant/libraries/`** inside your project. That folder is derived and re-fetchable: it is never included when you publish, and hand-edits to it do not stick (the next update overwrites them). Projects opened straight from the cloud keep the copy in the app's own cache instead, and the web editor keeps it in the browser's own storage (about 200 MB at most; the libraries you used longest ago make room first, never one of the open project's); nothing changes in how libraries behave. Clearing the browser's site data removes the web copy, and the next open reads the libraries again.

Library content is **read-only from the consumer side**. That includes an agent's edits: a `ds` block addressed at a library's styles (by its handle, `@acme/design-kit/Styles/default.ds`, or at the downloaded copy) is refused with the same sentence and writes nothing, and so is a file write or edit aimed at any of a library's files, its canvases included ("This is part of Acme Design System (@acme/design-kit). Library components can only be changed in the library project. Nothing was written."). Changing a library's styles or files from this project by hand (a token edit, the code editor, the color picker on a library token) is refused with a quiet notice, "This is part of Acme Design System. Library components can only be changed in the library project.", whose "Open the library project" button opens it: an edit there would be lost on the next update. To change a library, edit the library project itself (the row's "Go to library project" opens it) and, for published libraries, release a new version; consumers then pick it up by updating.

## When a library or component is unavailable

Missing state is never destructive and never silent:

- If a library is unreachable (offline, access revoked, deleted) but was fetched before, its components **keep rendering** from the copy you have; updates stop, and the library's row in the Assets tab wears a warning glyph. The row does not offer Update while degraded (the fetch cannot succeed); it surfaces its state and offers Remove. Select the row and a banner above its components says so in plain words, by cause (offline: "Acme Design System can't be reached right now"; the server rate limiting this connection: "can't be fetched right now" with "The server asked Brilliant to slow down.", and Brilliant asks again by itself; no access or a library that no longer exists: "can't be fetched right now"; an expired sign-in asks you to sign in again; a folder library reads "can't be found right now", "Its folder may have been moved or deleted."), with **Try again** (fetches it again right away; the banner goes away by itself once it works; while you are offline Brilliant also asks again by itself, every 15 seconds at first and then less often, so updates resume when you are back online), **Remove** (where the project's libraries can be changed), and **Open library page** (not for a folder library). Under it, "Last known components, 1.2.0" names the release your copy is, and the components stay placeable. A library that was never fetched shows the banner alone.
- If the downloaded copy of a library goes missing while Brilliant is running (the folder was deleted or cleaned up), placed components keep their look, and the copy is downloaded again by itself, once, the next time something needs it: opening Assets on that library, or a component being read from it. If that download fails, the library shows the same banner as any library that cannot be fetched, with **Try again**.
- If a library was deleted and a different one was later made at the same address (same handle and name), Brilliant does not take it for yours. One notice says "Acme Design System was replaced by a different library" ("Its address now belongs to another project. This project keeps the copy it has, and nothing was changed."), the library's banner says the same, the copy you have keeps working exactly as it is, and nothing from the other project is downloaded. This is checked by the project behind the address, not only by its name, so it can never happen without you being told. To use the new library, **Remove** the old one and add it again: removing a replaced library asks first ("Remove Acme Design System?"), because it also deletes the copy this project kept and cannot be undone. Components you already placed stay on your canvases and show as missing their library. In the web editor the browser remembers which project each library is, and its copy is keyed by that project, so it says the same thing with the same notice and banner (also after a reload); there, Remove forgets the remembered project, and adding the library again takes the new one. A browser whose storage was cleared starts over from the library the address has now.
- A placed component whose source cannot be found renders quietly, with no corner glyph on the canvas. **Select it** and the inspector's Component section leads with the specific reason in one plain sentence, with the act that helps when one exists:
  - "This component's library, Acme Design System, was removed from this project." with **Add it back**, which adds the library in one press: at the version the project last used, or for a pasted component the version it was copied at, otherwise the latest release. You see the usual "Added" notice; if the library is private, gone or you are offline, the same plain sentence as Add library says so and nothing changes.
  - "This component's library, Acme Design System, cannot be reached. You may not have access, or it may no longer exist." with **Show in Assets** (the library's row). Only when this computer has no copy that lists the library's canvases (never fetched, its copy deleted, its folder gone, access lost), or the listed canvas cannot be opened.
  - "Canvas \"Atoms/Buttonz\" is not in Acme Design System 1.2.0. Its canvases: Atoms/Buttons, Atoms/Inputs." with **Show in Assets**: the library is fine, the component's row names a canvas the release does not have. A row that names no canvas reads "Button names no canvas in Acme Design System 1.2.0. Its canvases: ..." instead. Up to six canvases are named, then "and 3 more". A folder library leaves out the version. The `edit` answer that wrote the row gave the same cause and canvases, naming the library by its `lib()` address. Write the row again with a canvas the release has.
  - "Button is no longer in Acme Design System 1.4.0." When you updated the library in this session, it offers **Go back to 1.2.0** (the version it was on); otherwise the sentence stands alone.
  - "Button was removed from this project. It keeps looking as it did." or "The canvas Atoms was deleted. Button keeps looking as it did." The sentence stands alone.
  - A placed component cannot be swapped for another. To use a different one, place it from the Assets view and delete the old one.
- Removing a library, or a master removed from a release, leaves instances in place with their last-known look; nothing is ever stripped from your canvases.
- If a downloaded copy of a library is damaged on this computer (a canvas file that cannot be read), Brilliant downloads it again by itself, once. If the fresh copy cannot be read either, one notice says so ("Part of Acme Design System could not be read") and the components from that canvas keep their last look.
- When two libraries use each other (A uses B and B uses A), one notice says so in plain words ("Two libraries use each other": "Acme Icons and Acme Design System each depend on the other. Remove one from the other's libraries to fix it."). An agent's update answer says it its own way: "Acme Icons uses Acme Design System, which already uses Acme Icons. That link is skipped; everything else works as usual." This is said whether one of the two came along with the other or your project uses both of them directly (then it can appear beside a "Two libraries want different versions of Acme Icons" notice, "This project uses 1.0.0 everywhere.", which is a separate fact).

# Home Screen: the project area

The main area of the home screen, beside the left panel (`reference/ui/home`).

**The header.** The top of the project area shows the selected place's name (All projects, Shared with you, Personal, or a team) and a **New project** button, which opens the New project page under it (name a new project, open a folder, or import from Figma). In a narrow window the button folds into a "…" menu at the end of the header, which still offers New project.

**The project area**, top to bottom:

- **Pinned**: your pinned projects in the selected place, as tiles, in your pinned order (at most eight, with **See all N** to show every pin and **Show less** to fold them again). Reorder pins in the left panel.
- **Recent**: up to eight projects you opened most recently, titled by the most recent window that holds one: **Today**, **Yesterday**, **This week**, or **Recent**.
- **Projects**: every project in the selected place, one row each. The **sort** at the right of the "Projects" header picks the order: **Last opened** (the default), **Name**, or **Date created** (newest first; a project whose creation date is unknown goes last). Each place remembers its own sort, and it syncs across your devices. The Pinned and Recent grids keep their own order.

A pinned project in the recent window shows in both grids and in the list, each with a small pin icon.

**Search results.** While there is a search, the grids step aside and the area lists **Projects · N** (the projects whose name, folder path or cloud address match) and then **Canvases · N** (every canvas whose name matches, project by project). Double-click a canvas row, or select it and press Enter, to open its project on that canvas.

**Tiles and rows.** A tile shows the project's cover, or a mosaic of up to four canvas thumbnails (with a "+N" badge when there are more), then the project name with its badges and a line saying where it lives and when you last opened it ("This Mac · 2h ago"). A row shows a small thumbnail, the name, where it lives (a folder icon for a project only on your computer, a cloud icon otherwise) with the badges, and when you last opened it. Hover a tile's or row's picture to see its canvas count and its full folder path (or its brilliant.design address). A canvas that has no thumbnail yet shows a plain gray cell (nothing is faked); missing thumbnails fill in the background for the projects on screen.

Right-clicking a tile or a row selects it and opens the same "…" menu described below (a pinned row in the left panel opens it too).

**Selecting and the keyboard.** Click a project to select it, double-click it or press Enter to open it. With a project selected, the arrow keys move the selection (in a grid, up and down move by a whole row, then on into the next section), Home and End jump to the first and last item, Escape clears the selection, Cmd+Enter (Ctrl+Enter on Windows) opens its brilliant.design page, Cmd+Delete (Ctrl+Delete on Windows) asks to delete a project that lives in a folder on your computer (the same "Delete project…" as the menu; a cloud-only project and Scratch are never offered), and Shift+F10 (or the keyboard's menu key) opens its "…" menu. Start typing a project's name to jump to it (the letters you type within a second form the name's start). A thin ring shows around the selected item while you drive it from the keyboard; the selection goes away when the project drops out of the view (a place, a search).

**A folder that went missing.** If a project's folder was moved, renamed or deleted outside Brilliant, its tile stays, dimmed, and reads "Folder not found · last seen 3d ago". Its menu offers **Locate…** (pick the folder where it went; the project takes its place in the list, and keeps its pinned spot) and, for a project that synced to the cloud from this computer, **Download again** (fetches a fresh copy into your `~/Brilliant` folder), then **Remove from list**.

**Badges** mean the same thing here as on the tabs: nothing = local only, a cloud icon = a public cloud project, a sync icon = a project that lives on both your computer and the cloud, and a lock is added when the project is private. A **team-owned** project additionally leads its badge cluster with the team's small square avatar, and that avatar is the whole team marker (no team name is added anywhere): tiles and rows show it always, and the left panel's pinned rows reveal it on hover with the rest of the cluster. A pinned project's badges start with a small pin. A team project of yours keeps the plain cloud icon (it is your work, not a foreign project), while a cloud project you have no access to still shows the dashed cloud. A project that is **view-only** for you (you can open it but not edit it) shows an **eye** after its other badges, the same as on its tab. A project marked as a **library** (other projects can depend on it; see `reference/libraries`) adds a small stacked-layers icon to its badge cluster, last in the cluster, on its tile, its list row and its pinned row in the left pane (a project tab does not show it); hovering it reads "Library" (or "Verified library", "Private library", "Public library") with ", latest 1.4.0" or ", no releases yet".

**The "…" menu** (hover a tile or a row to reveal it) offers, as they apply, in four groups separated by thin lines (open and share, then the file actions, then the list actions, then Delete on its own; right-clicking an open project's tab in the top toolbar shows the same menu without Open and with Close Tab, Close Others and Close to the Right; see `reference/ui/top-toolbar`):

- **Open**: open the project.
- **Open in web**: for published projects, opens the project's public page in your browser.
- **Checkpoints** (published projects): opens the project with the left panel on its Checkpoints tab.
- **Project settings…** (published projects): opens the project with the left panel on its Project tab, showing General.
- **Sharing…**: opens Settings -> Project for that project **without leaving home** (no tab switch). For a published project it shows the owner/sharing rows; for an unpublished local folder it opens the publish flow for that folder. On a **team project** this entry appears only for team admins (sharing on a team project is managed by its admins), so members simply do not see it.
- **Change cover…**: opens the same Settings page, whose Cover section picks the image the project's tile shows.
- **Make available offline**: for a cloud-only project, downloads a local copy into your `~/Brilliant` projects folder so it becomes a synced project (its badge flips to the sync icon). If a folder of that name already exists there, it tells you and does nothing. If the project holds two files whose names differ only in capital letters (`main.bl` and `Main.bl`) and your disk cannot tell them apart, one of them is downloaded (the capitalized one) and the finished notice names the file it skipped, so nothing is overwritten and nothing is lost silently; the cloud project keeps both.
- **Duplicate as local project**: for a cloud-only project, makes an independent local copy on your computer and opens it as a new project. Unlike Make available offline, the copy is **not** synced (it keeps no link back to the cloud project), so it is yours to edit freely. It never clobbers an existing folder (it lands beside one of the same name).
- **Rename…**: the project's name on the tile (or row) turns into a text field with the name selected; type the new name and press **Enter** (or click away) to rename, **Escape** to cancel. A local or synced project renames its folder on disk; a cloud-only project renames on the web (old links redirect). It renames exactly like double-clicking the project's tab title.
- **Show in Finder**: for projects that have a folder on disk.
- **Pin to top** / **Unpin**: adds the project to the pinned projects, or takes it out.
- **Remove from list**: drops the project from your list. It never deletes anything on disk or in the cloud. This works on the **Scratch** sandbox too: home normally always offers a Scratch row, and removing it puts that row away for good. Your scratch work is untouched on disk, and the row comes back if Brilliant ever opens the scratch workspace again (which it does when you have no other project to open). Removing a row only changes what your home screen lists: the project still exists, and an agent can still address it by name (it stays in `list_projects`).
- **Delete project…**: moves the project's folder to the Trash (the Recycle Bin on Windows); on Windows and Linux a confirmation that names the project asks first. Nothing is deleted for good. On a Mac the folder moves at once and the toast carries **Undo** for a few seconds, which puts the folder back where it was and lists the project again; afterwards (and on Windows and Linux) put it back from the Trash to get it back. If the project was open, its tab closes first. For a synced project this removes only the copy on this computer; the cloud copy stays and the project is still listed as a cloud project. Cloud-only projects (no folder) and the Scratch sandbox do not offer it.

With no projects at all, the project area shows a **Create your first project** card with **New project** and **Open folder…** (on a computer you can also drop a folder on it to open it as a project). A place with nothing in it says so ("No projects shared with you", "No personal projects") with **New project**, **Open folder…**, a **Sign in to see your cloud projects** link when you are signed out, and a **Show all** button that goes back to All projects. When a search finds nothing the project area says so ("No projects match" and your search) with a **Clear search** button.

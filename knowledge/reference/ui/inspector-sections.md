# Right Toolbar Sections (in order from top to bottom)

Top to bottom: Design System, Canvas, Strokes and Fills (for new shapes), Component, Element, Layout, Typography, Selection Strokes, Selection Fills, Selection Colors, Effects, Layout Grid, Export. Each section decides its own visibility based on the current selection and tool; this list reflects the slot order, not which sections are visible at any moment.

**Header** (above the section stack): the avatar / presence / Share cluster and the hover-revealed "…" options menu described in `reference/ui/right-toolbar` (Toggle All Sections lives in that menu). Zoom percentage sits on the right: drag to adjust, click to open a preset dropdown (2, 25, 50, 75, 100, 125, 150, 200, 300, 400, 600, 800, 1000, 2000, 3000, 5000). Below the levels, after a divider, the same menu offers **Zoom In**, **Zoom Out**, **Zoom to Fit** (frames all content) and **Zoom to Selection** (greyed out when nothing is selected), each with its keyboard shortcut shown on the right.

**Design System Section**: Brand dropdown plus one row per mode axis (theme first, density second, then alphabetical). Visible whenever the active canvas is loaded; lets users switch the design system, theme, density, and any custom mode axes the design system defines. Surfaces here only; token management itself lives in the design system file. See `design-systems/core`.

**Canvas Section**: Canvas background color swatch and toggle. Visible only when nothing is selected and the Move tool is active.

**New-shape defaults**: with nothing selected, the regular Strokes and Fills sections show with the subtitle "for new shapes": they hold the default strokes and fills that new rectangles and circles get. `+` adds one (several are allowed) and each row removes its own; an empty section means the app default, so there is no Reset. With nothing selected and the Move tool active, the panel shows, top to bottom: Design System, Canvas, Strokes and Fills (for new shapes), and Export last (just its header and `+`, see Export with nothing selected below). There is no Import section. The shape-tool shortcuts (R / Shift+R, O / Shift+O) still choose fill-only or stroke-only.

**Element Section**: at the very top, two always-visible icon rows (no expanding needed): **align** (left, horizontal center, right, top, vertical center, bottom, then center horizontally / vertically in the parent) and **arrange** (rotate 90° right / left, flip horizontal / vertical, distribute horizontally / vertically). Buttons the selection can't use are dimmed in place: aligning needs 2+ elements, or one element inside a frame (it aligns to the frame's edges, as in Figma); distributing needs 3+. Then X/Y position (type, drag, or use the arrow keys; X and Y have no preset menu, W and H do) (the row also holds the absolute-position pin button when the selection is inside an auto layout frame, and the "..." expander), W/H with a constrain-proportions toggle, sizing behavior (hug/fill/fixed per axis) ending in a ruler-icon toggle that reveals Min/Max W/H rows (auto layout frames and their direct children), a pin-constraints row (Figma's nine-nub widget plus horizontal and vertical pin dropdowns, shown for children of frames, components, instances, and non-hug groups and for absolute-positioned auto layout children, hidden where pins are dormant), rotation, opacity, corner radius (expand for per-corner or top/bottom pairs; an app-glyph toggle appears at nonzero radius and reveals a smoothing percent row for squircle corners), flex (for auto layout fill children; moves to its own row when the smoothing toggle shows), and circle arc properties (start angle, sweep, inner ratio) for circle elements. In vector edit mode with nodes or handles selected: shows node/handle position and point type instead of W/H/rotation/opacity. Boolean operations (union, subtract, intersect, exclude, use as mask) show as their own inline row whenever 2+ elements are selected, right in the section without expanding anything. The "..." expander exposes blend mode (containers get a Pass through default plus Normal and the standard modes) and absolute scale.

**Layout Section**: for frames and auto layout frames, the layout switch (None / Vertical / Horizontal), Wrap (Clip Content in its spot when the layout is None) and Resize to Fit (Option+Shift+Cmd+R); when every selected frame is auto layout: the alignment grid (a click picks main + cross alignment and leaves Auto; a double click on a cell switches Auto spacing on, and a double click while in Auto switches it off at that cell), Gap (Auto first in its menu), Cross gap when every frame wraps, and padding (one mode button switches between one value, horizontal / vertical pairs, and four sides). Groups, masks and booleans show no Layout section and the inspector has no parent type menu: convert a group with **Convert to Frame** (right-click menu or command palette), add auto layout with Shift+A or the layout switch, and un-mask with **Use as mask** in the Element section (see `reference/frames/nesting`). Layout guides for non-auto-layout frames live in the Layout Grid section.

**Typography Section**: Font family (click opens font selector) + font size + text direction toggle; line height + letter spacing + OpenType features button; font weight dropdown + text sizing mode (a four-segment control: Auto Size / Auto Width / Auto Height / Fixed, applied on click) + Auto Size button; text alignment (left/center/right) + italic + underline + strikethrough + a "..." expander (vertical alignment trio, list toggles, paragraph indent + list spacing, case + truncation, paragraph spacing). Visible when a text element is selected directly (alone or alongside other elements) or when the Text tool is active with nothing selected. Selecting a frame or group shows no Typography section for the text inside it (as in Figma): select the text itself to edit its type.

**Selection Strokes Section**: Per-stroke color swatch, thickness, and position (inside / center / outside) for the selected elements. For rectangles and frames each stroke's config row (under its color row) ends with a per-side width field (accepts "4", "4, 8", or "1, 2, 3, 4") plus pairs / individual editor toggles (see `reference/styling`). Stroke caps (start/end caps for open paths and arcs; unified cap dropdown for complex vectors). Add / remove buttons.

**Selection Fills Section**: Per-fill swatch (color, gradient, image, shader, or image-filter fill types: inner shadow, inner glow, background blur, color adjust, noise/grain, halftone, pixelate, duotone, posterize, dither). Add / remove buttons. For vector elements with regions, shows per-region fill controls. Clicking an image fill swatch opens the color picker in image mode: the image with a Replace button, the Fit menu (Fill, Fit, Crop, Tile), the image opacity, and your recent images (drag-and-drop and Cmd+V paste also replace it). Replacing the image keeps the fill's Fit mode, tile scale, opacity and blend. The picker's **Settings** section of an image fill has a **Remove Background** button: it cuts the photo's background to transparency in place (Brilliant AI, see `reference/ai`), shows a spinner while it works, and reads **Restore Background** on a fill whose background was removed, putting the original back. On a fill whose background was removed an **Add Outline** button sits beside it: it adds a white sticker outline around the subject as a new vector layer above the photo (see `reference/ai`). Remove Background (from the palette or the right-click menu) also works on a selected frame, group or component instance: it cuts every photo inside it in one step, undone with one Cmd+Z. When it cannot run, the right-click row and the button say why: "Remove Background (in progress)" while a cut is running, "Remove Background (fill hidden)" when the image fill's eye is off. An image whose file is gone (deleted, never synced, or unreadable) shows as a gray box on the canvas with a warning badge on its top-right corner (hover it for the reason and a Retry button), and its fill row reads "Image file missing" followed by the file name. Replace the image or restore the file to bring it back. Exports render the gray box (without the badge) and log a warning naming the missing file.

**Selection Colors Section**: Unified editor for the unique colors used across fills, strokes, and text-range span colors of the current selection. A text span colored with the same design token as another element's fill shares one row, and so do two bindings that resolve to the same token (the seed `primary` and its alias `color.primary` are one row, labelled with the more meaningful name, its count summed); the same token resolving to different colors under two brands or modes stays two rows, each label naming its brand, else its mode, else its resolved hex (for example "primary · dark" beside "primary · #0080FF"). Shown when the selection includes frame descendants. Each row is a plain color line (a paint's settings live in the color picker's Settings section). Clicking a row's ×N count selects every layer using that color; a text layer whose colored spans use it is selected as the layer, once (never a text range), and clicking while editing text leaves the text edit first. On a stroke color, the count is the way to its stroke settings: it selects those strokes, and Selection Strokes shows their config rows. The same count click works on the color rows of Selection Fills (including a text's span colors) and Selection Strokes.

**Effects Section**: Drop shadow, outer glow, element (layer) blur. Add and remove effects; a shadow's or glow's color, visibility and parameters open from its swatch in the color picker (its Settings section); an element blur's glyph opens the picker with only its Settings section (Radius and the Shown/Hidden toggle). Inner shadow, inner glow, and background blur are fill types (in the Fills section), not effects.

**Layout Grid Section**: Layout grid editor for frames. Three grid types: Grid (uniform cells), Columns, Rows. Per-grid: visibility toggle, color swatch, expand toggle for properties (count, gutter, margin, alignment, span), and remove button.

**Export Section**: Multi-config export panel. Each config row: format dropdown (PNG, JPEG, WebP, SVG, PDF, HTML, React, MP4, MOV, Replay; MOV is hidden on Windows). In the browser editor the video formats (MP4, MOV, Replay) are dropped from the dropdown: they need the native encoder, so video export is desktop-only (raster, vector, and markup all export on the web). The HTML entry exposes a second dropdown to pick the variant (Page = standalone document, Snippet, Flexbox). The Replay row shows a separate container dropdown that picks MP4 or MOV. Resolution preset (Original 1x/2x/3x/4x, 720p, 1080p, 1440p, 4K, 8K, Portrait Post · IG, FB, Square Post · IG, X, Story / Reel · IG, TikTok, iPhone 16 Pro, MacBook Pro 14", Custom; vector and markup formats hide the resolution row). Expand for advanced (width/height with constrain proportions, fit mode = Fit/Fill/Stretch/Repeat, background, PDF multi-page toggle, plus video duration / FPS / codec / quality and replay-specific pacing/intro for video and replay rows). Add multiple configs with `+` to export several formats in one click. The right-toolbar UI does NOT expose JPEG-quality, WebP-quality, or WebP-lossless toggles: those are only reachable via the MCP `export` tool.

**Export with nothing selected.** With nothing selected, the Export section still shows, as the last section of the panel: just its header and `+` until you add a config. `+` adds PNG 1x. These configs belong to the canvas (each canvas keeps its own while the app runs) and are separate from the configs you use for a selection. The button reads **Export <canvas name>** and exports the whole canvas as ONE image: everything visible, framed by the union of its top-level layers. The format list leaves out MP4, MOV and Replay, and the separate-files option does not apply. `-` can remove every config, back to the header alone. On an empty canvas, exporting shows "Nothing to export: this canvas is empty."

**Figma import** no longer lives in the inspector: a Figma file is imported through the Brilliant Figma plugin and the import screen, and a pasted Figma link goes into the "+" New project page (`reference/canvases/figma-import`). The paragraph below describes the former URL section, kept only for the agent command `import_figma`.

**Figma Import Section**: retired. The inspector no longer carries a Figma URL section; importing a Figma file goes through the Brilliant plugin and the import screen, and the "+" New project page's link field is where a link is pasted (`reference/canvases/figma-import`).

Fonts on Figma import: text keeps its real font whenever Brilliant can serve it on this machine, which covers bundled fonts, the whole Google Fonts catalog (downloaded on demand), fonts installed on the machine, and on macOS the Apple system families Figma names as SF Pro, SF Compact, SF Mono, and New York (they resolve to the installed San Francisco / New York faces automatically). A text font Brilliant cannot serve imports as editable text shown in a substitute (a close open font, else Inter) with the true family kept; the Typography section shows a warning glyph in the family field and a badge, "Kalam is not installed, shown in Caveat.", with **Replace** (the font picker, applied at once with undo) and **Install font files**; once the real font is installed the text switches back by itself. An icon font (a private symbols font) imports through the Figma plugin as pixel-true glyph outlines instead: the element is named "... (outlined: FontName)", and installing the font and re-importing restores editable icons. "Replace missing fonts" in the palette lists every substituted font in the project.

Glass effects imported through the file URL use calibrated Figma-default parameters (Figma's API strips the real ones), so they look close to Figma out of the box; a design with glass, variables, or library components raises the plugin-upgrade card offering the one-minute in-place upgrade to full fidelity.

Design tokens also surface in the color picker (its Library tab) and in numeric property fields that accept tokens (font size, line height, font weight, corner radius, padding). The Design System section at the top of the toolbar handles brand/mode switching only.

# Window Modes

Brilliant runs in two window modes, switched on a single window:

- **Studio** (default): a regular desktop window with title bar, shadow, resizable. Visible in the Dock. Launched on startup.
- **Overlay:** a borderless, always-on-top, transparent fullscreen layer above other apps. Hidden from the Dock. Summoned and dismissed via a global hotkey that works even when Brilliant is unfocused.

| Action | Shortcut |
|--------|----------|
| Toggle overlay mode (global, opt-in) | Ctrl+F |
| Toggle passthrough (overlay only) | Ctrl+A |
| Toggle desktop icons (macOS-only; overlay mode only) | Ctrl+I |

**Pan and zoom speed are adjustable.** Settings (Cmd+,) → General → "Input" has two fields, "Pan speed" and "Zoom speed" (percent, 100% default, dropdown steps 50 to 200, typed entry 25 to 400). Pan speed scales two-finger scroll panning (and the momentum it throws); zoom speed scales pinch and modifier+scroll zooming. Middle-mouse and space-drag panning stay 1:1 with the cursor, and keyboard zoom steps are unaffected. Applies immediately and persists across launches.

**Mouse wheel zoom direction can be flipped.** Right under them, "Invert zoom direction" (off by default) reverses which way a mouse wheel zooms (Cmd+wheel on Mac, Ctrl+wheel on Windows and in the browser). Pinch and trackpad scrolling keep their direction.

**Overlay mode is macOS-only and opt-in.** The whole feature (transparent window + global hotkey) is gated on `Platform.isMacOS`; the toggle and its actions are not shown on Windows, and `toggle_overlay_mode` / `toggle_pass_through` are in the Windows-disabled keybinding set. The "Overlay Mode" toggle lives in Settings (Cmd+,) → System, off by default. The Ctrl+F global hotkey is only registered while that toggle is on; with it off, Ctrl+F does nothing. Turning it off while in overlay auto-exits to studio. The setting persists across launches (SharedPreferences key `OverlayModeEnabled`). Settings → Permissions exposes the Accessibility row: accessibility access is required for the global hotkey to summon Brilliant from other apps.

In passthrough mode (overlay only), mouse clicks pass through Brilliant to the apps below. Studio window state (position, size, fullscreen, maximized) is saved before entering overlay and restored on exit. A restore whose display arrangement changed in the meantime (say a monitor was unplugged mid-overlay) re-centers the window on the active display instead of leaving it stranded off-screen. If the window ever does end up unreachable, the palette's **Center Window on Screen** re-centers it at its current size; it stays available even while a text or image file is open. The bottom toolbar sits slightly higher off the bottom edge while in overlay mode than in studio.

**Window size and position persist across launches on macOS and Windows.** Relaunching restores the previous studio window frame, and a window left zoomed (macOS: Option+green, or the maximized state on Windows) comes back filling the same display's work area. The frame is saved as you move and resize, and again on quit. Only frames you are responsible for are saved: whatever happens to the window in the first moments of a launch is ignored, so a tiling or auto-arranging window manager (AeroSpace, yabai, Amethyst, Moom and friends) laying the window out at startup does not overwrite the size and position you left behind. Move or resize the window yourself and that frame is saved as usual. A frame saved on a since-disconnected monitor, or on one whose resolution changed, is pulled back fully inside a live display's work area instead of opening off-screen; on macOS that work area already excludes the menu bar (so the title bar never lands under the notch) and the Dock. Fullscreen is deliberately not persisted: leave fullscreen and quit, and you get the last normal frame back. The first run opens centered at about 80% of the primary work area (capped at 1400x900 logical), and the window cannot shrink below 800x600. Overlay mode never affects the saved frame: the studio frame is stored before entering overlay, and the overlay's own fullscreen layer is never written to it.

The overlay-mode toggle is a global hotkey only when the opt-in is on, so it works even when Brilliant is not the focused application. Reassigning the keybinding re-registers the global hotkey. Passthrough is a regular in-app shortcut gated to overlay mode (its WhenClause requires `!isStudioMode`, so the overlay window must be active). Toggle desktop icons is gated to overlay mode as well: it fires only while the overlay window is active, exactly like passthrough. Hiding the desktop restarts Finder for a clean overlay screenshot, so triggering it in a normal studio window (by keyboard or from an AI agent) is refused with a message telling you to enter overlay mode first. It remains a macOS-only operation (the command hard-returns off macOS).

**Hover highlight.** Settings (Cmd+,) → General → "Detailed hover highlight" under Appearance. Off (default): hovering the canvas outlines only the element under the cursor, the way Figma does. On: the hover also outlines the hovered frame's children (dashed) and its parent (dotted), and marks the fill or stroke under the cursor. Persists across launches.

**Small screens in the browser.** When the browser editor's window is small (narrower than 768 px or shorter than 500 px, a phone or a narrow window alike), it switches to AI focus: the top bar, the bottom toolbar and the AI chat stay, the side panels go. The Focus / Full switch (or Cmd+Shift+\\) takes you to the full UI; a choice made on a small screen is remembered in that browser until the window is large again (800 by 532 px or more), when the size decides again and you get back the mode you had before. A window that merely got small never changes the mode you chose on a large screen. Cmd+\\ (Ctrl+\\ on Windows and Linux) hides all UI at any size, as on the desktop. Crossing the line keeps your selection, an open text edit, the AI box and its draft, and the view. The desktop app is unchanged. Each project keeps its own Focus or Full, on the desktop and in the browser, and keeps it through a rename: a project returns in the mode you left it in, and a project you open for the first time takes the last mode you chose (the file switcher Focus shows in the top bar on the desktop, and in the canvas's top-left control in the browser: `reference/canvas/window-modes`, `reference/ui/top-toolbar`).

**UI density.** Settings (Cmd+,) → General → "UI density" under Appearance: Normal (default, roomier text and spacing) or Compact (fits more on screen). Also available as commands in the palette: "UI Density: Normal", "UI Density: Compact", and "Toggle UI Density" (all unbound by default; assign a shortcut in Keyboard Shortcuts). Applies to all app chrome instantly; canvas content is unaffected. Persists across launches and, when signed in, syncs across devices (see "Settings sync" below). This is app-chrome density, distinct from the design system's density mode axis in the inspector's Design System section.

**Settings sync.** When signed in, portable settings follow the account across desktop and web: keyboard shortcut overrides, tool and UI preferences, theme (light/dark/system), UI density, extra enabled AI models, and onboarding state. Changes sync automatically in the background (a couple of seconds after an edit, and on app focus); the newest change per setting wins. Signed out, everything stays purely local. Signing into a different account on the same machine starts from that account's own settings and onboarding state: nothing carries over from the previous account, and only a machine that was never signed in seeds its local settings into the first account, once. Provider API keys never leave the machine: they are stored locally (keychain on desktop, browser storage on web) and are never uploaded.
